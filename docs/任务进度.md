## 4. Step 1 进度：Artifact Boundary Audit

```text
Status: Completed
Started At: 2026-06-12
Completed At: 2026-06-12 10:20 CST
```

### 目标

盘点当前 specs 字段、生产者、消费者和 artifact boundary，判断哪些字段属于：

- coder-facing strict specs；
- planning internal IR；
- sidecar；
- validator-only artifacts；
- 当前边界不清或风险较高的字段。

### 应检查路径


### 预期输出

```text
docs/specs_optimization/01_artifact_boundary_audit.md
```

### 完成记录

```text
Completed Work:
- 静态审查三类 strict specs schema、planning compiler/lowering、coder loader/models、header renderer、source/repair prompts 和 validators。
- 建立字段级 producer/consumer 矩阵，区分 loader、header、source prompt、repair prompt、schema validation 和 semantic validation 消费。
- 审查完整 planning 输出样例、sidecars、dependency graph、validation reports 和已有 coder compile failure 日志。
- 明确 strict specs、planning internal IR、pure sidecar、validator-sidecar 和 validator-only artifact 边界。

Artifacts:
- `docs/specs_optimization/01_artifact_boundary_audit.md`
- `docs/任务进度.md`

Key Findings:
- `PUBLIC_SYMBOLS`、`ACCESS_PATHS`、`CALL_CONTRACTS`、`FORBIDDEN_SYMBOLS`、`WIRE_MAPPING`、`TEST_VECTORS` 等字段通过 `raw` 被 prompt 或 validator 隐式消费，不能仅依据 coder dataclass 判断其可删除性。
- compiler 当前从同一 `imports_allowed` 同时生成 `SOURCE.DEPENDENCY` 和 `HEADER.DEPENDENCY`，未区分 source call dependency 与 public header/type dependency，也未生成 `HEADER.SYSTEM_DEPENDENCY`。
- deterministic dependency fallback 会清空 `calls_allowed` 和 `imports_allowed`；已有样例中 `call_contracts` 非空但 function edges/imports 为空，dependency validation 仍 passed。
- planning coder compatibility validation 使用 `validate_rendered_headers=False`，无法拦截已有 `ssize_t` missing system include 等 deterministic header compile failure。
- `planning_decisions.json` 和 `planning_ir_refs.json` 是 validator-sidecars；`planning_traceability.json` 当前是 pure sidecar。
- `DOC_REF`、`PROTOCOL.SCOPE`、部分 nested `ROLE`、function `PUBLIC_SYMBOLS` 是优先 sidecar/omit 候选；`SOURCE.DATA`、structured signature/contract 等字段更可能需要强化 consumer，而不是直接移出 strict specs。

Blockers:
- 无。Step 1 静态审计已完成；未运行 Step 2 工具或大规模实验。

Next Step Recommendation:
- Step 2 优先支持 dependency/header/type closure diff 与 fail-closed diagnostics，其次支持 `calls_allowed`、`call_contracts`、`imports_allowed`、`signature_dependencies` 的跨层一致性检查。
- Step 2 不得通过清空 dependency 字段、删除所有 dependency edges 或降低 coder compatibility validation 强度制造通过结果。
```
