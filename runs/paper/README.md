# SpecForge 三轮四协议实验数据

本数据集包含三轮 MQTT、CoAP、HTTP/1.1 和 SMTP 生成实验，共 12 次独立尝试。前两轮来自稳定性实验，第三轮为项目整理后的验证实验；三轮共同构成论文使用的实验数据集。

## 数据组织

```text
runs/paper/
├── README.md                 数据集范围、指标及结果
├── summary.json              三轮总计、逐协议及逐场景记录
├── runs.csv                  12 次尝试的指标表
├── stages.csv                各阶段耗时、Token 和模型调用数
├── round_01/                 第一轮四协议原始数据
├── round_02/                 第二轮四协议原始数据
├── round_03/                 第三轮四协议原始数据
└── source_records/
    ├── stability/            前两轮的原始汇总、冻结配置和审计
    ├── validation/           第三轮的原始汇总、冻结配置和整理审计
    └── relocation.json       逐项移动映射与内容校验
```

每轮保留生成日志、模型调用记录、规格、交付项目、构建报告和独立验收记录。原始文件按字节保留；其历史命令、路径、时间和哈希不改写。当前与历史位置的对应关系记录在 `summary.json` 的 `source_mapping` 中。原始编排及统计脚本作为运行记录保存，当前数据读取以数据集索引为准。

原始数据在本地完整保留。Git 同步本说明、JSON 汇总和两张 CSV 表；原始日志及交付目录沿用本地保存规则。

## 实验设置与指标

三轮使用同一组四协议任务、标准输入、模型配置、响应上限及验收器。记录中的模型为 `deepseek-flash`，使用 high reasoning、thinking enabled、非流式和 65,536 Token 输出上限。完成生成后分别执行普通及 ASan/UBSan 构建与行为验收。

12 次尝试均从新任务开始，不恢复前次运行、不复用前次中间产物、不人工修改交付。独立验收不参与生成修复。

- 生成通过：完成全部生成阶段，交付一致性和开发关卡通过。
- 完整独立通过：普通与 sanitizer 两种验收的所有必需场景均实际执行并通过。
- 总 Token：输入加输出；推理包含在输出中，缓存命中包含在输入中。
- 模型调用数：有记录的模型完成响应数，一个响应可以包含多个工具调用。
- 轮次耗时：原始记录的单轮计时。各轮耗时相加不包含实验日期之间的间隔。
- 协议总耗时：生成、独立验收及外层编排的实际经过时间。
- 阶段记录：行为规格阶段包含首次审查；实现阶段包含其触发的规格修订、重审和实现续修。未进入的阶段保留未执行状态；阶段表中的 pending 表示未进入该阶段。

“构建”包含最终开发关卡的普通、sanitizer、交付构建，以及独立验收的普通和 sanitizer 构建。11 个完成生成的项目均通过这些构建。第二轮 CoAP 在语义审查阶段达到响应上限，逐需求审查记录未完成，未执行编码、构建和独立验收。

每种独立验收模式共有 156 个计划场景，实际执行 146 个，通过 138 个，未通过 8 个；第二轮 CoAP 的 10 个场景未执行。两种模式分别运行和记录。

未通过记录包含第一轮 HTTP 的四项连接提前结束场景、SMTP 的 DATA 长度上限场景；第二轮 SMTP 的 VRFY 与 TURN 回复码场景；第三轮 SMTP 的 TURN 回复码场景。逐场景状态和原始错误信息保存在 JSON 汇总及各次独立报告中。
